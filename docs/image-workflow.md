# 图片工作流

公众号图片的核心问题是：公众号后台需要能访问图片。如果 Markdown 里还是本地图片路径，复制到公众号后台后很容易丢图。

## 推荐流程

```text
本地图片或 AI 生成图片
-> PicGo / PicList 上传
-> Cloudflare R2 或其他图床
-> 得到公网图片 URL
-> 写入 Markdown
-> 公众号排版插件渲染
-> 复制到公众号后台
```

## 两类图片

### 固定图片

固定图片包括：

- 头图
- 尾图
- 二维码
- 固定关注引导图

这些图片建议只上传一次，然后把 URL 放进公众号模板。

模板中可以这样写：

```markdown
![头图](https://你的图床域名/path/header.jpg)
```

```markdown
![尾图](https://你的图床域名/path/footer.jpg)
```

### 每期插图

每期插图包括：

- 文章中间的解释图
- AI 生成配图
- 截图
- 手绘图
- 数据图

这些图片应该在写作过程中按需上传，并插入到正文对应位置。

如果文章不需要插图，不要强行生成。

## Obsidian 中插图的建议

推荐最终保留在 Markdown 里的图片写法是：

```markdown
![图片说明](https://你的图床域名/path/image.jpg)
```

不推荐发布稿中保留：

```markdown
![[image.png]]
```

也不推荐：

```markdown
![图片](C:\Users\name\Pictures\image.png)
```

这些本地路径在公众号后台通常不可用。

## PicGo / PicList 的作用

PicGo 或 PicList 的作用是把本地图片上传到图床，然后把图片地址复制回来。

常见做法：

1. 配置 R2 或其他对象存储。
2. 配置自定义域名。
3. 在 PicGo / PicList 中测试上传。
4. 确认返回的是 `https://` 开头的公网链接。
5. 把链接写入 Markdown。

## R2 注意事项

如果使用 Cloudflare R2，建议：

- 绑定自定义域名。
- 不要在公开仓库里提交访问密钥。
- 不要把 bucket 的管理凭证写入 Markdown。
- 发布前确认图片 URL 可以在未登录状态下打开。

## 和 AI 出图的配合

AI 出图只负责生成图片，不负责让公众号后台稳定读取图片。

推荐链路是：

```text
AI 生成图片 -> 保存到本地 -> 上传图床 -> 插入公网 URL
```

如果你有独立的出图 skill，可以让公众号写作 skill 在需要插图时提示用户：

```text
这篇文章是否需要插图？
如果需要，我会调用出图流程，并把图片上传到图床后插入正文。
```

## 发布前检查

发布前请检查：

- 图片是否都是公网 URL。
- 图片是否能在无登录状态下打开。
- 固定头图和尾图是否存在。
- 每期插图是否放在合适位置。
- 图片说明是否简洁。
- 是否误用了本地绝对路径。
